PART A — IMPLEMENT THE CRM EXPORT CONTRACT
------------------------------------------

PRIMARY OUTCOME

Make the primary Copy TSV, Download TSV, and Download CSV actions produce
exactly these ten columns, in exactly this order and spelling:

| PROSPECT_FIRST_NAME | PROSPECT_LAST_NAME | DESIGNATION | EMAIL_ID | COMPANY_NAME | COMPANY_SIZE | COUNTRY | INDUSTRY_TYPE | WEBSITE_NAME | LINKEDIN_URL |
| ------------------- | ------------------ | ----------- | -------- | ------------ | ------------ | ------- | ------------- | ------------ | ------------ |

This is a strict integration contract. Do not add, rename, reorder, or
silently overload default-export columns. Use UTF-8 and retain CSV quoting,
UTF-8 BOM download support, Unicode, and spreadsheet formula-injection
protection.

FIELD RULES

1. PROSPECT_FIRST_NAME
   - Use the evidence-backed person's first token after safe title cleanup.
   - Leave it blank if the name cannot be safely interpreted.

2. PROSPECT_LAST_NAME
   - Preserve every remaining name token so global/multi-word surnames such as
     “de la Cruz”, “van der Meer”, and “von Trapp” are not lost.
   - A one-word name gets a blank last-name cell.
   - Do not guess comma-ordered or otherwise ambiguous names.

3. DESIGNATION
   - Export only the accepted current role for that person at that company.
   - Never promote a former, ex-, or unverified role into a current role.

4. EMAIL_ID
   - Export a Hunter-verified address, an allowed provider-supported address,
     or the product's clearly labelled supported estimate when existing rules
     allow it. Otherwise leave it blank.
   - Never manufacture an email address merely to fill the column.

5. COMPANY_NAME, COMPANY_SIZE, COUNTRY, INDUSTRY_TYPE
   - Use source-backed company facts from the existing research pipeline.
   - Preserve blank cells when a fact is unavailable; do not infer or invent.

6. WEBSITE_NAME
   - Export only the canonical public company domain/site already established
     by the evidence pipeline. Never synthesize a domain from the company name.

7. LINKEDIN_URL
   - Export a real person-profile LinkedIn URL only (for example /in/ or /pub/)
     that was actually found and accepted by the existing evidence logic.
   - Never put a company LinkedIn URL, official-site evidence URL, search URL,
     constructed URL, or guessed URL in this field.

8. NO FABRICATED PROSPECTS
   - A company with no accepted person must generate zero CRM prospect rows.
   - Keep “needs review”, source-blocked, or rejection diagnostics in the UI
     and optional audit data; never force a diagnostic into a prospect field.

IMPLEMENTATION REQUIREMENTS

- Make the 10-column CRM schema the default in lib/parse.js buildTSV/buildCSV.
- Add a small pure, unit-tested name-splitting function.
- Make CSV derive from the same schema as TSV, without losing formula safety.
- Explicitly preserve any useful historical layouts as named, opt-in formats
  only (for example legacy 7-column and audit/evidence formats). They must
  never replace or silently modify the primary CRM export.
- Update popup.js, results.js, popup.html, and results.html so the visible
  primary controls say “CRM” and “10 columns”. If a legacy control remains,
  label it honestly as legacy.
- Ensure filter/search exports retain every required company field, especially
  WEBSITE_NAME, in both popup and full results views.
- When a filtered view has no accepted prospects, show a useful message instead
  of copying a misleading review row.
- Do not weaken the existing evidence, official-source, current-role,
  anti-hallucination, email, pause/resume, permission, or security controls.
- Do not add credentials, API keys, tracking, hidden telemetry, or private-data
  collection. Do not bypass authentication walls, CAPTCHAs, or website controls.

REQUIRED TESTS AND VERIFICATION

Add or update deterministic tests that prove all of the following:

- The default TSV and CSV headers have exactly ten values in the exact required
  order and spelling.
- Correct mapping for every column, including a source-backed website domain.
- Name splitting: ordinary names, multi-token/particle names, titles, one-word
  names, and ambiguous comma-ordered names.
- Blank email/company fields remain blank; they are never fabricated.
- An official-company-source person with only an evidence URL has a blank
  LINKEDIN_URL in CRM output.
- Formula-looking name, company, email, and other exported values are escaped
  as text for spreadsheets.
- Unicode and comma quoting survive CSV generation.
- A company with no accepted people produces no CRM person row.
- Legacy/audit formats remain explicitly callable and keep their intended
  behavior if you retain them.
- Filtered exports from popup and full results retain WEBSITE_NAME.

Run every repository verification command you can run locally, including:

  node tools/test.mjs
  node tools/diag_linkcheck.mjs
  node tools/eval-evidence.mjs
  node tools/live-eval-evidence.mjs --offline

Also run JavaScript syntax checks, parse the manifest as JSON, inspect the git
diff, and perform an unpacked Chrome/Edge smoke test when the environment can
support it. Fix all reproducible failures before committing. Report exact
commands and results in your final handoff, but never claim “bug free”; say
what was actually verified and any remaining environment-limited checks.
